## 2026-07-01-11 - 移除 Bash 自动注入

- 用户目标：修复 Kimi app 启动后 Bash 工具找不到 `/bin/bash` 的问题，避免 app 覆盖 Kimi Code 自身 Bash 定位。
- 涉及目录：`apps/kimi-shell/src-tauri/src`、`apps/kimi-shell/src/features/control-center`、`.ai/changes`。
- 修改内容：将 `kimi_locator::locate_shell_path()` 简化为只透传有效的显式 `KIMI_SHELL_PATH`；删除 Git Bash 常见路径和 PATH `bash` 自动猜测；安装面板不再把未配置 shell override 显示成缺 Git Bash；新增最小单元测试覆盖显式路径存在、缺失和未设置场景。
- 修改原因：app 自动猜测可能把 Windows WSL shim `bash.exe` 注入给 Kimi Code，导致 Kimi Code 自身定位逻辑被覆盖。
- 本次已消除的不确定性：确认 backend 启动、doctor、安装探测都复用同一个 `locate_shell_path()`；只改共享定位函数即可收口影响。
- 本次采用的关键假设：Kimi Code 自身负责 Bash 定位；`KIMI_SHELL_PATH` 只作为用户显式 override。
- 剩余不确定性：仍需在桌面 app 实际启动路径下手工确认 Kimi Code 自身定位到可用 Bash。
- 影响范围：backend 启动环境变量、Kimi doctor 环境变量、安装探测与控制中心中的 shell override 状态。
- 验证方式：`cargo test kimi_locator`；`cargo test kimi_locator --no-run`；`cargo check`。
- 是否更新 README：否，本次未改变目录职责或公共使用契约。
- 是否更新 `.ai/architecture`：否。
- 是否需要新增或更新 `.ai/decisions`：否。
- 后续注意事项：若未来确实需要 app 托管 shell 定位，应作为显式配置能力重新设计，不再静默猜测 PATH。
