## 2026-07-14-12 - 接入小助手本体签名自动更新

- 用户目标：让 Kimi 小助手自动检测新版本，并在用户点击后下载和安装更新。
- 涉及目录：`apps/kimi-shell`、`.github/workflows`、`.ai/architecture`、`.ai/decisions`、`tasks`。
- 修改内容：接入 Tauri Updater 检测/下载/安装链路和设置页状态；新增 tag 发布 workflow，生成 NSIS/MSI、签名与 `latest.json`；补齐长期决策与发布门禁。
- 修改原因：用 Tauri 原生签名更新能力替代自定义下载器，并将更新资产纳入可重复的 GitHub Release 流程。
- 本次已消除的不确定性：更新 endpoint、签名边界、Windows 安装模式、NSIS/MSI manifest 选择、tag/version 约束和发布所需工具链均已固定。
- 本次采用的关键假设：`0.1.13` 为首个支持 Updater 的版本；legacy Windows manifest 优先 NSIS；用户必须显式确认安装。
- 剩余不确定性：真实 GitHub Release 资产与旧 NSIS/MSI 安装来源的端到端行为需在首次 tag 发布后验证。
- 影响范围：桌面应用设置页、退出生命周期、Tauri 权限/配置、Windows 发布流程；不改变 Kimi Code 自身升级流程。
- 验证方式：Shell TypeScript、Vitest、安全 gate、Rust `cargo check`/`cargo test --no-run`；workflow diff/语法检查；发布前执行 updater G3 矩阵。
- 是否更新 README：是，更新根 README 与 Shell README 的能力、环境和发布入口。
- 是否更新 `.ai/architecture`：是，登记当前更新链路与 G3 验证门。
- 是否需要新增或更新 `.ai/decisions`：是，新增 accepted 的签名桌面自更新 ADR。
- 后续注意事项：两个签名 Secrets 已配置；不得把签名私钥或密码写入仓库、命令行或日志；密钥丢失会切断已安装客户端的更新信任链；Tauri 签名不替代 Windows Authenticode。
