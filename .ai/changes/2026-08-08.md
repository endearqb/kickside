## 2026-08-08-19 - 控制中心 API 编辑退场与登录浏览器放行

- 用户目标：控制中心不再提供 API 配置编辑，改为引导到 Kimi Code Web 内置设置；保留认证展示与诊断，并放行启动登录验证的系统浏览器跳转。
- 涉及目录：`apps/kimi-shell/src/features/control-center`、`apps/kimi-shell/src/app`、`apps/kimi-shell/src-tauri/src`、`.ai/architecture`、`tasks` 与根文档。
- 修改内容：API 面板改为只读展示认证模式、Kimi 登录和 Provider API 健康/来源/时间/摘要；移除全部编辑控件并增加 Kimi Code Web 设置入口；iframe 外链消息补齐 bridge nonce；增加 UI 与登录链接回归测试。
- 修改原因：API 配置归属已转移到 Kimi Code Web；直接 iframe 外链桥遗漏 nonce，导致登录链接被拦截后又被父窗口静默拒绝。
- 本次已消除的不确定性：确认 Kimi 登录由 Web 内置 OAuth 链路触发；确认 `--no-open` 只禁止启动时自动打开本地 Web UI；确认系统浏览器 opener、HTTP(S) 校验、command 注册与 capability 完整。
- 本次采用的关键假设：仓库没有稳定设置深链，因此使用返回工作区并打开内置设置的保守引导；本次启动登录验收范围是默认主 Code pane。
- 剩余不确定性：真实 Windows 默认浏览器、OAuth 完成后的状态刷新，以及非默认次级 Code pane 登录仍需 G3 验证。
- 影响范围：控制中心 API 编辑入口退场；认证/诊断数据契约、后端配置 commands、Kimi 启动参数和 URL scheme 限制不变。
- 验证方式：针对性 Vitest 2 files / 11 tests、全量 Vitest 38 files / 197 tests、TypeScript、Vite build、安全 command/capability gate、tracked Markdown 路径 gate、`cargo check` 与 `cargo test --no-run` 均通过；真实 OAuth 浏览器链路列为 G3。
- 是否更新 README：是，更新根 README 与 Shell README 的控制中心和 Web 外链职责。
- 是否更新 `.ai/architecture`：是，更新当前事实与手工发布门。
- 是否需要新增或更新 `.ai/decisions`：否；未删除已发布 command 或改变序列化契约。
- 后续注意事项：支持升级的旧版本完成一个发布周期后，再通过单独 ADR 评估配置写入兼容 commands；若次级 Code pane也需独立登录，补 per-pane 安全外链路由。
