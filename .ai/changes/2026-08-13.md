## 2026-08-13-12 - Windows CMD shim 后端归属修复

- 用户目标：修复 0.1.23 Windows 安装版在 Kimi Code 已安装且服务已启动时仍显示“后端异常”和“缺失”。
- 涉及目录：`apps/kimi-shell/src-tauri`、`.ai/changes`、`tasks`。
- 修改内容：Windows registry owned candidate 从只接受启动器 PID，扩展为接受该 PID 的当前进程树；增加 ToolHelp 进程快照 feature 和真实 CMD 子进程测试；安装探针统一复用 `kimi_locator`。
- 修改原因：pnpm/npm 的 `kimi.CMD` 由 `cmd.exe` 派生 Node 服务，registry 记录的是 Node PID；合并后的严格 PID 等值校验误拒绝了真实服务。安装页另用 canonical `\\?\` 路径直接执行 CMD，会返回失败并误报缺失。
- 本次已消除的不确定性：本机 `kimi.CMD --version` 返回 0.34.0；backend.log 显示 56560 已 ready；app.log 显示启动 PID 与 registry PID 不同，随后因 15 秒内找不到同 PID registry 而失败。
- 本次采用的关键假设：CMD 派生进程属于应用本次创建的 Windows 进程树；仍需 registry 时间窗口、loopback、health 和 bearer auth 全部通过才能接管。
- 剩余不确定性：本地安装包的真实升级安装与应用启动需用户完成 G3；macOS 签名/公证仍未配置。
- 影响范围：Windows npm/pnpm Kimi Code 启动与安装检测；Unix/macOS PID 等值规则和安全验证不变。
- 验证方式：`cargo fmt --all -- --check`、instance registry 专项 7 项、Rust 全量 264 项、`cargo clippy --locked --all-targets -- -D warnings`、前端生产构建、Bridge sidecar 构建、本地关闭 updater artifact 后的 NSIS/MSI 构建。
- 是否更新 README：否；没有改变已记录的平台职责或运行方式，而是恢复 README 声明的 npm/pnpm shim 支持。
- 是否更新 `.ai/architecture`：否；不改变架构方向或验证入口。
- 是否需要新增或更新 `.ai/decisions`：否；属于 Windows 兼容性 bugfix。
- 后续注意事项：用户安装新包后应确认启动直接进入工作区、Kimi 显示已安装、退出后不残留本次启动的 Node 服务树。

## 2026-08-13-12 - macOS Kimi Code native 升级修复

- 用户目标：修复 macOS 不显示 Kimi Code 0.35.0 可升级状态，以及执行 native `kimi upgrade` 后仍停留 0.34.0 却报告成功。
- 涉及目录：`apps/kimi-shell/src-tauri`、`apps/kimi-shell/src/features/control-center`、`apps/kimi-shell/README.md`、`.ai/decisions`、`tasks`。
