## 2026-08-23-17 - DSH 官方 latest 轻量跟随与受控更新

- 用户目标：根据附件完成 DSH 修复后，进一步让壳应用无需发布新版 KickSide 即可由用户主动升级到 DeepSeek 官方 latest，且不引入过重的签名清单系统。
- 涉及目录：`apps/kimi-shell`、`.github/workflows`、`.ai/architecture`。
- 修改内容：更新检测与安装统一为一次 npm 官方 `latest` 元数据读取，将返回版本和 sha512 integrity 冻结为本次精确目标，npm 始终安装 `@deepseek-ai/dsh@<SemVer>` 而不是可变 `@latest`。`0.1.1-rc.2` 只保留为 published/CI tested baseline；运行兼容从枚举 allowlist 改为最低 `0.1.0-rc.6` + 有效 SemVer/canonical 固定入口。保留已发布 `recommendedVersion/state/updateAvailable/compatible` 语义，以 additive `officialVersion/officialState/officialUpdateAvailable/installedSupported` 承载官方目标和最低基线。此前完成的 6 小时缓存、私有 npm cache、integrity、staging 后停机、停止 epoch、验证/隔离/回滚和终态进度继续复用。控制中心统一显示当前版本、官方最新和“用户主动 · npm latest”，覆盖正常升级、重装、低基线修复与 ahead 替换。
- 修改原因：固定编译期推荐版本要求每次 DSH 放行都发布 KickSide，与壳应用只托管官方 runtime 的定位不匹配；直接执行 `@latest` 又会让检查和安装时刻的目标漂移，因此选择“latest 发现、精确版本安装”的轻量边界。
- 本次已消除的不确定性：2026-08-23 npm 官方元数据确认当前 `latest=0.1.1-rc.2`、bin 仍为 `lib/bin.js` 且提供 sha512 integrity；包元数据没有 `engines` 字段，因此继续以 KickSide 自有 Node 22.19/24 + `parseEnv` gate 为准。动态目标由纯函数测试使用未来 `0.1.1-rc.3/rc.9/rc.99` 覆盖，不依赖当前 latest 恰好仍为 rc.2。
- 本次采用的关键假设：DeepSeek npm 官方发布即兼容授权；用户主动点击才升级。远程签名兼容清单、预构建 runtime bundle、Gitee/GitHub runtime 下载源、preview 通道和后台静默升级不在本轮建立。
- 剩余不确定性：Windows/macOS × Node 22.19/24 的远端 canary 尚需 PR CI 复跑；Windows WebView2、npm shim、代理 registry 与安装包进程树仍属于 G3。完成态所在受限沙箱拒绝 loopback bind 并使 Chrome headless `SIGABRT`，对应 Rust socket 测试、latest alias smoke 与视觉 gate 需在非受限 CI/宿主复跑。二进制/目录回滚不能逆转未来上游可能写入的不可逆用户数据迁移，这是信任官方 latest 的明确取舍。
- 影响范围：现有 rc.6 及更高有效版本继续可启动；未来官方 SemVer 新版无需发布 KickSide，用户检查后即可主动安装。安装期间旧 DSH 保持可用，切换与启动验证阶段仍有短暂停机。
