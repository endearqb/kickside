# v0.2.0 Unsigned macOS Preview Release

## Status

Accepted

## Context

The accepted macOS V1 ADR requires normal public macOS releases to use Developer ID signing,
notarization and stapling. It allowed one explicit ad-hoc exception for `v0.1.24`. The product owner
has now explicitly requested that `v0.2.0` also ship without Apple Developer ID credentials so the
cross-platform preview, DeepSeek Harness integration and Kimi Code layout work can be distributed
for testing. Tauri updater signing secrets remain configured and are independent from Apple code
signing.

## Decision

- Permit exactly the `v0.2.0` tag to build the Apple Silicon `.app` / DMG with Tauri
  `signingIdentity: "-"` and without notarization or stapling.
- Keep the Tauri updater private key and password mandatory for both platform updater artifacts.
- Require the Release body to start with `⚠️ **macOS 版本未签名、未公证**` and describe the manual
  Gatekeeper path, supported architecture and remaining G3 gaps.
- Label `v0.2.0` as a preview. Do not describe its macOS artifact as Developer ID signed, notarized,
  stapled, Gatekeeper-trusted or production-ready.
- Keep the workflow fail-closed for every tag other than `v0.2.0`. A later release must restore the
  normal signed/notarized workflow or receive a new explicit accepted decision; this exception does
  not become a standing unsigned channel.
- Publish only after both Windows and macOS build jobs produce the required installers and updater
  signatures and the workflow generates the single cross-platform `latest.json`.

## Rationale

- The user made the security and trust trade-off explicit; encoding the exact tag and mandatory
  warning prevents the prior exception from silently broadening.
- Updater signatures preserve the existing application-update trust boundary even though they do
  not replace Apple Developer ID or Windows Authenticode trust.
- Keeping the Release in draft until the complete asset matrix succeeds prevents a partial platform
  release from becoming Latest.

## Consequences

- macOS users may need to allow the app manually in System Settings, and Gatekeeper trust is not
  established.
- Windows installers still do not gain Authenticode or SmartScreen reputation from the Tauri
  updater signature.
- Automated and release-asset gates do not substitute for the documented Windows/macOS manual G3
  matrix; publication authorizes distribution as a preview, not a dual-platform production claim.
- The next version is blocked until the Release workflow is changed away from the exact `v0.2.0`
  exception.

## Verification

- Statically verify tag/package equality, exact-tag restriction, release-note warning, required
  updater secrets, ad-hoc macOS configuration and draft-only failure behavior.
- Require GitHub Actions to verify Windows NSIS/MSI, macOS app/DMG, both updater signatures and the
  final `latest.json` before publishing.
- After publication, inspect the Release body, asset matrix, updater manifest platforms and macOS
  ad-hoc/no-Authority evidence from the workflow.
