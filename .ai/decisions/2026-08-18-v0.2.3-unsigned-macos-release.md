# v0.2.3 Unsigned macOS Release Exception

## Status

Accepted

## Context

The normal macOS public release path requires Developer ID signing, notarization and stapling. The repository currently has the Tauri updater signing key but no Apple Developer ID or notarization credentials. The product owner explicitly requested a `v0.2.3` release after the same warning-first `v0.2.2` flow so the already implemented LAN access and selectable GitHub/Gitee update sources can reach users.

## Decision

- Permit only the exact `v0.2.3` tag to use `src-tauri/tauri.macos.unsigned.conf.json` and an ad-hoc macOS identity.
- Require the release notes to begin with `⚠️ **macOS 版本未签名、未公证**` and state that the package is not Developer ID signed, notarized, stapled or Gatekeeper-trusted.
- Keep the Tauri updater artifacts signed with the existing updater key. Continue producing and validating Windows NSIS/MSI, macOS app archive/DMG, updater signatures and the cross-platform manifest.
- Keep the workflow fail-closed for every other tag. A later release must restore Developer ID signing/notarization/stapling or obtain another accepted exact-tag exception.
- This exception authorizes distribution for testing and incremental upgrades only. It does not authorize claims of a trusted or production-ready macOS release.

## Verification

- Statically require exact tag/package equality, the warning-first release notes and updater signing Secrets.
- On Apple Silicon CI, verify the app and sidecar architecture, require `Signature=adhoc`, reject any Apple signing authority, and require exactly one app archive, signature and DMG.
- Preserve all manual release gates documented in `.ai/architecture/verification-gates.md`; automated asset checks do not substitute for clean-account Gatekeeper, installer or runtime G3.
