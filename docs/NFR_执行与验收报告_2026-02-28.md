## 2. 验收口径

- 性能口径（NFR-01）：`应用进程启动 -> Loading 页面可见` 小于 1 秒（通过埋点字段输出）。
- 可靠性口径（NFR-03/04）：支持自动化脚本回归，验证重复启动/关闭无泄漏、端口冲突可恢复。
- 安全口径（NFR-05/06）：启动参数固定本地回环绑定；远程页面不授予高权限 Tauri 能力。

## 3. NFR 总览

| NFR 编号 | 目标 | 状态 | 验收方式 |
|---|---|---|---|
| NFR-01 | 壳窗口启动 < 1s（Loading 先显示） | 已实现（埋点） | 诊断页读取 `loadingStartupMs/loadingSlaMet` |
| NFR-02 | 后端就绪后自动跳转并给反馈 | 已实现 | 状态页/诊断页显示 `backendReadyMs` + 自动导航 |
| NFR-03 | 反复开关不泄漏后台进程 | 已实现 | `pnpm check:nfr:reliability` |
| NFR-04 | 端口占用时自动恢复 | 已实现 | `pnpm check:nfr:port-conflict` |
| NFR-05 | 默认仅本机访问 | 已实现 | 启动参数固定 `--host 127.0.0.1` |
| NFR-06 | 不向 Web UI 暴露高权限 API | 已实现 | capability 收敛 + `pnpm check:nfr:security` |
| NFR-07 | 尽量依赖稳定 CLI 参数与健康检查 | 已实现 | 新增 `cli_contract` 合约检查 |
| NFR-08 | 日志可定位问题 | 已实现 | `app.log/backend.log` + 轮转 + 诊断字段 |

### 4.3 NFR-03 可靠性（进程泄漏）

已落地：

- 新增自动化可靠性脚本 `nfr_reliability.ps1`，覆盖重复启动/关闭场景。
- 新增固定起始端口环境变量 `KIMI_SHELL_BASE_PORT` 便于稳定回归。

代码与脚本位置：

### 4.4 NFR-04 端口冲突恢复

已落地：
- 启动时扫描 `base_port..base_port+9` 的 `/healthz`。
- 新增冲突场景脚本：占用 base port 后验证恢复到后续端口。

代码与脚本位置：
- `apps\kimi-shell\src-tauri\src\port_manager.rs`
- `apps\kimi-shell\scripts\nfr_port_conflict.ps1`

### 4.5 NFR-05 默认本机访问

已落地：
- 启动参数由统一构造函数生成，固定为：
  - `web --no-open --host 127.0.0.1 --port <port>`
- 未引入 `--network/--public` 默认能力。

代码位置：
- `apps\kimi-shell\src-tauri\src\backend_manager.rs`

### 4.6 NFR-06 权限最小化

已落地：
- capability 从 `dialog:default` 收敛为 `dialog:allow-open`。
- 显式 `local: true`，不配置 remote URL 授权。
- 新增静态能力扫描脚本防回退。

代码与脚本位置：
- `apps\kimi-shell\src-tauri\capabilities\default.json`
- `apps\kimi-shell\scripts\check_capabilities.mjs`

### 4.7 NFR-07 可维护性

已落地：

- 必要参数缺失时直接失败并给出诊断错误，减少依赖上游内部行为。

代码位置：
- `apps\kimi-shell\src-tauri\src\cli_contract.rs`
