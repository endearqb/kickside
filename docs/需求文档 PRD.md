# 需求文档 PRD（轻量壳方案）

## 1\. 文档信息

-   产品名：**Kimi Desktop Shell（暂定）**
    
-   版本：v0.1（MVP）
    
-   目标平台：macOS / Windows / Linux（但能力受 `kimi` 本身支持情况影响）
    
-   依赖：用户本机已安装 **Kimi Code CLI（**`kimi` **命令可用）**
    
-   参考：Kimi Code CLI Web UI 参考文档（`kimi web` 选项、端口策略、访问控制等）
    

* * *

## 2\. 背景与问题陈述

### 2.1 背景

Kimi Code CLI 提供了 `kimi web`：在本机启动 Web UI 服务并通过浏览器访问，具备更丰富的会话管理、文件操作和可视化体验。

### 2.2 现有痛点

-   用户需要手动：
    
    -   打开终端、进入目录、运行 `kimi web`
        
    -   等待启动后浏览器自动弹出（可能打断工作流）
        
-   难以做到：
    
    -   全局快捷键一键呼出/隐藏
        
    -   常驻托盘、快速切换
        
    -   关闭窗口后自动回收后台进程（避免端口占用/僵尸）
        

### 2.3 产品机会

用桌面壳（Tauri）把 `kimi web` 变成“像桌面 App 一样好用的 Web UI”：

-   **桌面壳只做系统集成与可靠性**
    
-   **所有业务能力复用官方 Web UI**（天然同步更新）
    

* * *

## 3\. 产品目标与非目标

### 3.1 目标（Goals）

MVP 必须达成：

1.  **零业务重写**：不实现自定义聊天 UI，不做 IPC 对接业务逻辑，只加载 `kimi web` 页面
    
2.  **无感启动**：启动桌面 App 时后台自动启动 `kimi web`（禁用自动打开浏览器）
    
3.  **稳定呈现**：自动处理端口冲突，确保 WebView 能加载到可用地址（支持默认端口策略或自选端口）
    
4.  **可靠退出**：退出桌面 App 时能可靠终止后台服务进程（不残留占用端口）
    
5.  **桌面体验**：托盘菜单 + 全局快捷键（呼出/隐藏）
    
6.  **依赖检测**：检测 `kimi` 是否存在；不存在时给出安装/配置引导（不强行代装）
    

### 3.2 非目标（Non-goals）

-   不打包/内置 `kimi` 二进制（遵循“依赖用户安装”路线）
    
-   不重写 Web UI、也不 fork 修改上游 `kimi-cli`
    
-   不提供“公网暴露 Web UI”的一键能力（安全风险大；最多作为高级开关并强警告）
    
-   不保证 `open-in` 在所有平台可用（上游实现目前限制 macOS）
    

* * *

## 4\. 目标用户与使用场景

### 4.1 用户画像

-   开发者/工程师：已经在使用 Kimi Code CLI，希望更“桌面化”的入口
    
-   重度多任务用户：需要快速呼出/隐藏，不希望切换浏览器或终端
    

### 4.2 核心场景

1.  **快速呼出**：写代码时按热键呼出 Kimi UI，提问/审批/查看结果，再按热键隐藏
    
2.  **常驻托盘**：不占任务栏/不干扰桌面，托盘点击即用
    
3.  **多目录工作**：默认使用上次目录；必要时切换工作目录后重启后台（可选 MVP+）
    
4.  **离线/弱网容错**：Web UI 启动失败时提示原因与重试入口（例如端口冲突、找不到 `kimi`）
    

* * *

## 5\. 功能需求（MVP）

### 5.1 启动与依赖检测

-   FR-01：App 启动时检测 `kimi` 命令可用性
    
    -   优先：在 PATH 中查找
        
    -   若失败：提示“未检测到 kimi”，给出安装指引与“选择 kimi 可执行文件路径”入口（可选）
        
-   FR-02：检测到 `kimi` 后启动后台服务：
    
    -   执行：`kimi web --no-open ...`（必须禁用自动打开浏览器）
        

### 5.2 WebView 加载策略

-   FR-03：后台服务未就绪时显示 Loading（壳内页面）
    
-   FR-04：服务就绪后 WebView 跳转到本地地址（例如 `http://127.0.0.1:<port>`）
    
    -   端口策略：默认遵循上游（5494 起，最多尝试 10 个端口）或壳自行随机起始端口
        
-   FR-05：如果后台服务异常退出/启动失败，展示错误页（包含错误摘要 + 重试按钮 + 查看日志入口）
    

### 5.3 桌面集成：托盘与快捷键

-   FR-06：托盘图标（系统托盘）
    
    -   菜单项（MVP）：
        
        -   打开/隐藏窗口
            
        -   重启后台服务
            
        -   打开日志目录
            
        -   退出（Quit）
            
-   FR-07：全局快捷键（默认 `CmdOrCtrl+Shift+K`，可配置）
    
    -   行为：toggle 主窗口（显示/隐藏 + 聚焦）
        

### 5.4 退出与进程回收

-   FR-08：退出 App（Quit）时：
    
    -   先尝试优雅终止 `kimi web`
        
    -   超时则强杀
        
    -   确保不会残留导致下次端口占用
        

* * *

## 6\. 可选需求（MVP 之后）

-   FR+01：工作目录管理
    
    -   记住上次启动目录（作为 `kimi web` 的 current\_dir）
        
    -   提供“选择目录并重启服务”
        
-   FR+02：诊断页
    
    -   展示：`kimi --version`、启动参数、当前端口、最近错误
        
-   FR+03：多窗口/多实例（谨慎）
    
    -   每个窗口单独一个 `kimi web` 实例（多端口、多进程）
        
    -   风险较高：资源占用、会话/配置互相影响（需验证）
        

* * *

## 7\. 非功能需求（NFR）

### 7.1 性能

-   NFR-01：壳窗口启动 < 1s（Loading 先显示）
    
-   NFR-02：在后台服务就绪后自动跳转，不要求“秒开”，但要给反馈
    

### 7.2 可靠性

-   NFR-03：反复打开/关闭窗口不导致后台进程泄漏
    
-   NFR-04：端口被占用时自动恢复（避免白屏）
    

### 7.3 安全

-   NFR-05：默认只允许本机访问（不启用 `--network`）
    
-   NFR-06：不在 Web UI 页面中暴露高权限的 Tauri JS API（降低“本地端口被劫持/内容被替换”时的风险）
    

### 7.4 可维护性

-   NFR-07：尽量不依赖上游内部实现（只依赖稳定 CLI 参数与健康检查）
    
-   NFR-08：日志可定位问题（启动命令、stdout/stderr、端口、退出原因）
    

* * *

## 8\. 已知限制与产品声明

-   **必须依赖用户安装** `kimi`：壳不负责内置。
    
-   **上游仍处 Technical Preview**：CLI/Web UI 行为可能调整，需要版本兼容策略。
    
-   `open-in` 当前实现仅 macOS 可用（Windows/Linux 上会报“仅支持 macOS”）。
    

* * *

## 9\. 验收标准（MVP）

1.  用户已安装 `kimi`：
    
    -   启动壳 → 不弹系统浏览器 → 窗口内显示 Web UI
        
2.  端口冲突：
    
    -   5494 被占用时仍能成功加载（自动换端口或随机端口）
        
3.  退出可靠：
    
    -   Quit 后后台 `kimi web` 不再监听端口
        
4.  快捷键与托盘：
    
    -   快捷键可在任何应用前台时 toggle
        
    -   托盘菜单可打开/隐藏/退出
