**把“工作目录”变成一个一等公民**，用系统右键把“上下文（目录/文件选择）”喂给壳，再由壳去拉起/重启 `kimi web`。你现有实现里已经有“后台进程管理、随机端口、/healthz 探活、单实例、托盘、日志、优雅退出”等关键积木，所以这件事属于**增量功能**，不是推倒重来。

下面我按“你要的两个右键场景”拆解：可行性评估 → 需要解决的关键点 → 推荐实现方案（Windows 为主，顺带给 macOS/Linux 的落地方式）。

## 1) 想法评估：好在哪里、坑在哪里

### 好处

1.  **工作流极短**：右键 → 打开 GUI → 直接在目标目录上下文里用 Kimi（比“终端 cd + kimi web”短太多）。
    
2.  **文件选择场景的“复制到工作区”很聪明**：
    
    -   避免对原文件夹做任何副作用（尤其是 AI 工具可能生成中间文件、输出等）。
        
    -   让会话/操作具有可复现性（工作区就是一次任务的快照）。
        
3.  **跟** `kimi web` **的行为天然契合**：`kimi web` 的“启动目录（startup\_dir）”就是进程启动时的 `cwd`，你只要用不同 `current_dir` 拉起它就能切换工作目录。你现在也已经把“重启后端”打通了。
    

### 关键坑（但都能工程化解决）

1.  **多文件选择时，Explorer 可能会“启动多次你的 exe”**  
    这是 Windows 上常见行为。解决方式不是强行 COM ShellExtension（太重），而是：
    
    -   你已经有**单实例**能力；第二次/第 N 次启动会把参数转发给主进程。
        
    -   主进程做一个“**短时间 debounce 聚合器**”，把 200–500ms 内收到的多个文件路径合并成一次“批处理”，只创建一个工作区文件夹。
        
2.  **复制大文件会慢/占空间**  
    MVP 先照你的要求“复制”，但建议预留开关（后面可支持 hardlink/symlink/只复制引用清单）。
    
3.  **切换目录意味着必须重启** `kimi web`  
    如果用户在旧会话里正跑任务，突然右键打开另一个目录会把后端重启掉，体验可能“打断”。  
    MVP 可以接受（就是“切换工作区”），但建议加一个可选策略：
    
    -   **当前有会话/任务时弹提示：在新窗口打开（未来多实例）or 直接切换**。

## 2) 你要实现的两个右键行为，建议统一成一个“OpenRequest 协议”

你描述的其实是两类输入：

### A. 右键任意目录空白处 / 文件夹：以该目录作为工作目录打开

-   输入：`dir_path`
    
-   行为：`work_dir = dir_path` → 启动/重启后端 → 展示窗口
    

### B. 右键选择一个或多个文件：复制到默认工作目录下的新文件夹，再以新文件夹作为工作目录打开

-   输入：`file_paths[]`
    
-   行为：
    
    1.  `base_dir = 默认工作目录（用户设置）`
        
    2.  生成 `workspace_dir = base_dir/yyyyymmdd-文件名-随机码`
        
    3.  把选中文件复制到 `workspace_dir/`
        
    4.  `work_dir = workspace_dir` → 启动/重启后端 → 展示窗口
        

> 注意：你现在进度里 FR+01（工作目录管理）还没纳入 MVP，这个功能会“顺便把 FR+01 补上”。

## 3) 壳侧实现方案（Tauri/Rust）：最推荐的做法

### 3.1 给桌面壳加一个 CLI 参数协议

让你的 `kimi-shell.exe` 支持被系统右键调用：

-   `--open-dir <path>`
    
-   `--open-files <path>...`（或直接把剩余参数都当文件路径）
    

解析策略建议“宽松”一点，避免不同平台/不同右键传参差异导致失败：

-   如果收到的参数里存在 `--open-dir`：取后一个参数当目录
    
-   否则如果存在 `--open-files`：把后续所有参数当文件列表
    
-   否则：把所有非 `--` 开头参数当路径；对每个路径 `metadata()` 判断 file/dir
    

然后统一转换成：

```rust
enum OpenRequest {
  OpenDir(PathBuf),
  OpenFiles(Vec<PathBuf>),
}
```

### 3.2 多文件选择“聚合处理”（关键）

即便你设置了 Windows 的 MultiSelectModel，实际环境仍可能出现“多次启动”。所以我建议你**必做**这个聚合器，它能让功能鲁棒。

实现思想（主进程里）：

-   维护一个全局 `Vec<PathBuf>` 缓冲 + 一个“定时器任务”句柄
    
-   每次收到 `OpenFiles(files)`：
    
    -   把 files 追加进缓冲（去重）
        
    -   取消上一次定时器
        
    -   启动新定时器：`sleep(350ms)` 后触发一次 `process_files(buffer.clone()); buffer.clear()`
        

这样 Explorer 就算一口气把 20 个文件分别启动 20 次，你也只会创建一个工作区目录。

> 单实例转发你可以继续用 `tauri-plugin-single-instance`，它的回调能拿到 `args` 和 `cwd`，你在回调里把 args 转成 `OpenRequest` 再丢给聚合器即可。 ([Tauri](https://v2.tauri.app/plugin/single-instance/?utm_source=chatgpt.com))

### 3.3 生成工作区目录名：`yyyymmdd-文件名-随机码`

建议落地规则（避免路径非法/过长）：

-   `yyyymmdd`：本地时间日期（例如 `20260228`）
    
-   `文件名`：
    
    -   单文件：用 `file_stem()`（不含扩展名）
        
    -   多文件：用 `"{first_stem}_etc{n}"` 或直接 `"{n}files"`（更短更稳）
        
-   `随机码`：6 位 base32/hex（例如 `a3f91c`）
    
-   **sanitize**：把 Windows 不允许的字符替换为 `_`，并限制长度（比如最多 40 字符），防止超长路径
    

最终：`20260228-report_etc3-a3f91c`

### 3.4 复制文件到工作区目录

MVP 用 `std::fs::copy` 就够了，但要补齐这些细节：

-   目标同名冲突：`foo.txt` 已存在则改成 `foo (2).txt`
    
-   复制失败要给出可读错误（权限/占用/不存在）
    
-   复制过程较久：
    
    -   UI 可显示 “Copying N files…”（你已有 loading/error 三态页结构，很好加）
        

> 如果你后面要“更快更省空间”：Windows 可用 hardlink（同卷）/ sOS/Linux 用 symlink。可以作为 v0.2+ 的可选项。

### 3.5 把“工作目录”接入你现有 BackendManager

你现在已经有：

-   状态机
    
-   重启/停止
    
-   随机端口 + `/healthz` 探活
    
-   日志落盘
    
-   退出清理
    
-   单实例聚焦  
    这些都能复用。
    

你只需要把 `start_backend()` 改成接受 \`work\_dir: Pat

-   `Command::new(kimi_path).current_dir(work_dir)`
    
-   参数仍是：`kimi web --no-open --host 127.0.0.1 --port <随机起始端口>`（你现在已这么做）
    

**注意**：切换工作目录 = 必须重启后端，因为 `kimi web` 的 star启后端”就是正确解法）。

## 4) Windows 右键菜单集成：无需管理员权限的最小实现

你要的右键入口，本质是给 Explorer 注册几个“静态 verb”。**推荐注册到 HKCU\\Software\\Classes（当前用户）**，不需要提权：Microsoft 文档也明确 HKCR 是 HKCU+HKLM 的合并视图，可以在 HKCU 下注册自定义谓词，优点是不需要提升权限。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/shell/context-menu-handlers?utm_source=chatgpt.com))

### 4.1 目录空白处右键（在该目录打开）

注册表位置（当前用户）：

-   `HKCU\Software\Classes\Directory\Background\shell\KimiWebShell`
    

命令里用 `%V` 传“当前目录”。微软社区给出的 PowerShell 右键项就用的是 `%V`（`Set-Location -literalPath '%V'`）并且路径正是 `Directory\Background\shell\...\command`，说明这个占位符在这个场景可用。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/answers/questions/2198576/windows-11-ltsc-2024-power-shell-bug?utm_source=chatgpt.com))

### 4.2 右键文件夹本身（以这个文件夹打开）

-   `HKCU\Software\Classes\Directory\shell\KimiWebShell`
    
-   参数用 `%1`（经典的 Shell 关联参数占位符）。Microsoft Learn 在“verb 命令字符串”示例中就用 `"%1"`，并强调要给它加引号以处理空格路径。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/shell/fa-verbs?utm_source=chatgpt.com))
    

### 4.3 右键文件（复制到工作区再打开）

-   `HKCU\Software\Classes\*\shell\KimiWebShell`
    

多选支持建议：

-   给这个 verb 设置 `MultiSelectModel = Player`：微软文档说明 Player 表示支持“任意数量的项”的选择模型。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/shell/how-to-employ-the-verb-selection-model))
    
-   但我仍建议你做“debounce 聚合器”（见 3.2），这样即使 Explorer 仍然多次启动也不会出错。
    

### 4.4 你可以怎么“写入/卸载注册表”

两条路线都行：

**路线 A（最省事、最可控）：应用内提供开关**

-   设置页加个按钮：`启用资源管理器右键菜单` / `禁用`
    
-   Rust 用 `winreg` crate 写 `HKCU\Software\Classes\...`
    
-   卸载时用户点“禁用”即可（或保留无伤大雅）
    

**路线 B（更产品化）：安装器写入/卸载清理**

-   NSIS 比较好加 registry 写入
    
-   MSI/WiX 也能做，但配置更麻烦
    

MVP 我建议先 A，验证体验后再 B。

## 5) 一个“能直接照抄”的 Windows 注册表样例（概念示例）

> 下面仅示意键结构与参数，不要直接复制就导入：你需要把 `YOUR_EXE_PATH` 换成实际安装路径（或让 App 自己写注册表更稳）。

```reg
Windows Registry Editor Version 5.00

; 1) 在文件夹空白处右键：打开该目录
[HKEY_CURRENT_USER\Software\Classes\Directory\Background\shell\KimiWebShell]
"MUIVerb"="Open Kimi Web Shell here"
"Icon"="\"YOUR_EXE_PATH\""

[HKEY_CURRENT_USER\Software\Classes\Directory\Background\shell\KimiWebShell\command]
@="\"YOUR_EXE_PATH\" --open-dir \"%V\""

; 2) 右键文件夹本身：打开该文件夹
[HKEY_CURRENT_USER\Software\Classes\Directory\shell\KimiWebShell]
"MUIVerb"="Open Kimi Web Shell"
"Icon"="\"YOUR_EXE_PATH\""

[HKEY_CURRENT_USER\Software\Classes\Directory\shell\KimiWebShell\command]
@="\"YOUR_EXE_PATH\" --open-dir \"%1\""

; 3) 右键文件（可多选）：复制到工作区再打开
[HKEY_CURRENT_USER\Software\Classes\*\shell\KimiWebShell]
"MUIVerb"="Open in Kimi Web Shell (Copy to Workspace)"
"Icon"="\"YOUR_EXE_PATH\""
"MultiSelectModel"="Player"

[HKEY_CURRENT_USER\Software\Classes\*\shell\KimiWebShell\command]
@="\"YOUR_EXE_PATH\" --open-files \"%1\""
```

-   `%V` 在 `Directory\Background` 场景用于指代当前目录（微软社区 PowerShell 右键项示例就是这么配的）。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/answers/questions/2198576/windows-11-ltsc-2024-power-shell-bug?utm_source=chatgpt.com))
    
-   `%1` 是 verb 命令字符串里最常见的“被选中对象路径”占位符，且务必加引号。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/shell/fa-verbs?utm_source=chatgpt.com))
    
-   `MultiSelectModel=Player` 用于声明该 verb 支持多选模型。 ([Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/shell/how-to-employ-the-verb-selection-model))

## 6) macOS / Linux 怎么做（如果你要跨平台）

你现在主要产物是 Windows（MSI/NSIS），但我也给你“同等语义”的跨平台落地路径：

### macOS（Finder）

-   推荐：**Quick Action（Automator 服务）**
    
    -   输入：选中的文件/文件夹 or 当前 Finder 目录
        
    -   动作：运行你的 `Kimi Desktop Shell.app` 并把路径作为参数传进去
        
-   如果要更深度：Finder Sync Extension（更复杂，不建议 MVP）
    

### Linux（Nautilus / Dolphin）

-   GNOME Files：放一个脚本到 `~/.local/share/nautilus/scripts/`
    
-   KDE：Service Menu（`.desktop` 服务菜单）
    
-   都是“把路径作为 argv 传给你的 app”，壳侧逻辑复用同一套 `OpenRequest`。
