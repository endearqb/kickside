# 控制中心 UI/UX 重设计计划

## Summary
基于 `frontend-design` skill，这次重设计采用“编辑化仪表台”方向，并按你选择的“允许重组”执行：保留现有核心功能、动作和状态来源，但重构控制中心的信息架构、视觉系统和交互节奏，让它从“配置卡片集合”升级为“可读、可操作、可导航的控制工作台”。

## Key Changes
- 重构信息架构为 3 层：`概览总览`、`快速设置/引导`、`运行与诊断`，把当前并列的概览/引导/运行中心改成更清晰的主次结构。
- 概览页改为真正的“主舞台”：顶部放系统健康摘要、关键状态和高频动作；中部放可点击的任务分组卡；把“引导完成度/右键菜单/Bridge/日志”改成有优先级的运营式摘要，而不是均质指标格子。
- 引导区从“长列表折叠卡片”改成“进度驱动流程”：左侧或顶部显示步骤进度与当前建议动作，右侧显示当前步骤详情，减少来回展开/收起的负担。
- 运行与诊断区改成“状态 + 深挖”模式：先显示异常、风险和最近日志摘要，再进入详细面板，避免用户先被大块底层诊断字段淹没。
- 统一控制中心及关联弹窗的视觉语言，包括 [ControlCenterView.tsx](D:/MyProject/kimi-app/apps/kimi-shell/src/features/control-center/ControlCenterView.tsx)、[ControlCenterCardHeader.tsx](D:/MyProject/kimi-app/apps/kimi-shell/src/features/control-center/ControlCenterCardHeader.tsx)、[ControlCenterModalShell.tsx](D:/MyProject/kimi-app/apps/kimi-shell/src/features/control-center/ControlCenterModalShell.tsx) 及对应样式，形成一致的标题层级、状态徽标、动作区、分组容器和留白体系。
- 为 `fullscreen/full` 与 `modal/dashboard` 两种容器分别设计：全屏版是完整工作台，模态版是“浓缩控制面板 + 跳转入口”，不再只是全屏布局的缩小版。
- 建立一套新的控制中心设计 token：更有辨识度的字体组合、非默认的色彩层级、背景肌理、状态色和动效节奏，但继续兼容现有 light/dark 主题切换。
- 优化 UX 细节：更明确的主按钮层级、危险动作分区、状态提示位置、空状态文案、长路径展示、日志可读性、移动端与窄窗断点下的导航折叠策略。

## Interfaces / Implementation Notes
- 不改后端接口、不改 `useShellController` 的业务动作签名；优先保持 `ControlCenterView` 现有 props 和 handler 契约稳定，降低联动风险。
- 允许在控制中心内部新增轻量展示层模型或局部子组件，用于把原始状态整理成“摘要卡/任务卡/状态条/步骤轨道”等新 UI 结构。
- 样式重心放在 [App.css](D:/MyProject/kimi-app/apps/kimi-shell/src/App.css) 与必要的局部组件结构调整；如需提炼设计 token，补充到现有主题变量体系而不是另起一套孤立样式。
- 关联弹窗保留现有功能流和打开方式，只重做布局、视觉层次和表单可读性，不改变保存/关闭/刷新等核心行为。

## Test Plan
- 渲染验证：全屏控制中心、工作区模态控制中心、dashboard chrome、full chrome 四种组合都能正确显示。
- 交互验证：导航切换、步骤切换、弹窗开关、Escape 关闭、主动作按钮、危险动作按钮均保持原行为。
- 状态验证：安装中、未配置、运行中、错误、Bridge 启动中、日志为空等典型状态都能正确映射到新 UI。
- 响应式验证：桌面宽屏、窄窗、平板/移动断点下，导航、摘要卡、步骤区和弹窗不破版。
- 视觉回归验证：light/dark 两个主题下对比主要页面和关键弹窗，确保对比度、层次和可读性达标。

## Assumptions
- 默认把“控制中心”范围包含主控制中心视图及其直接关联弹窗的视觉统一，但不扩展到工作区主界面或 titlebar 全量重做。
- 默认保留当前所有核心功能、业务文案语义和操作入口，不做后端逻辑或流程规则变更。
- 默认不新增全新模块，只重组现有模块的入口与呈现方式。
- 默认以“编辑化仪表台”为主视觉方向，强调品牌感、信息层级和长期使用效率，而不是炫技型赛博风。
