# 启动窗口双窗口交接改造方案

## Summary
- 目标文档路径：`apps/kimi-shell/docs/startup-dual-window-handoff.md`
- 目标：用“`prefill` 可见窗口 + `main` 隐藏预热窗口”替换当前单 `main` 窗口的 `show -> hide -> navigate -> show` 启动链路，彻底消除 prefill 与应用页之间的窗口闪烁。
- 成功标准：
  - Windows/WebView2 冷启动时，不再出现 prefill 与 shell 之间的原生窗口闪烁或同窗体尺寸突变。
  - 启动失败、重试、打开日志、退出应用的能力继续保留在 prefill 窗口。
  - `workspace`、`onboarding`、`diagnostics`、`control-center` 路由行为不回退。
  - 现有 `prefill-chat`、`shell-route`、workspace session bridge、open-request error 事件语义保持不变。

## Key Changes
### 窗口模型
- `main` 改为 shell 专用窗口，不再承担 prefill 载体职责。
- 新增 `prefill` 窗口，专门承载启动中、失败恢复、重试、日志入口。
- `main` 配置固定为：
  - label: `main`
  - url: `index.html#/loading`
  - create: `false`
  - visible: `false`
  - width/height: `1200 x 820`
  - minWidth/minHeight: `900 x 640`
- `prefill` 配置固定为：
  - label: `prefill`
  - url: `prefill.html`
  - create: `false`
  - visible: `false`
  - width/height: `720 x 520`
  - minWidth/minHeight: `660 x 460`
- 删除 `MainWindowSurface` 和“同一窗口在 prefill/shell 两套尺寸间切换”的逻辑；`apply_window_surface` 不再负责在同一窗口上切换启动面和应用面。

### 启动时序
1. 应用 setup 阶段先创建并显示 `prefill`，记录 `PrefillSurfaceShown`。
2. 紧接着在主线程创建隐藏的 `main`，让它直接加载 `index.html#/loading`，并在隐藏状态下完成 `notify_frontend_ready` 与 `report_loading_rendered`。
3. 后端启动、CLI 定位、contract 校验、workspace proxy 初始化继续按现有逻辑执行；这些过程只更新 prefill 状态，不得驱动任何可见窗口切页。
4. `complete_startup_monitor_route` 只负责确定目标路由并设置 `handoff_requested = true`，不得再调用“隐藏可见窗口后导航 shell”的逻辑。
5. 只有同时满足以下条件时，才允许 handoff：
   - `handoff_requested == true`
   - `frontend_ready == true`
   - `loading_rendered == true`
   - `startup_guard_failed == false`
6. handoff 顺序固定为：
   - 若已有目标路由，先把 `shell-route` 发给隐藏的 `main`
   - 刷新 pending main events / pending prefill
   - 读取 `prefill` 的位置，尽量把 `main` 放到同一显示器并以 prefill 中心点为参考居中
   - 关闭 `prefill`
   - `show + focus main`
7. 启动期内禁止出现 `hide visible window -> navigate shell -> show same window` 这条链路。

### 失败与重试
- 启动守卫失败时，必须保持或恢复 `prefill` 为唯一可见窗口，并把失败详情通过 `prefill-status` 发到 `prefill`。
- 守卫失败后，如果隐藏的 `main` 已存在，必须先 `hide` 再 `close`，避免残留脏窗口参与下一轮重试。
- `retry_start_backend` 触发后，必须重置 startup guard、重新创建隐藏的 `main`、重新进入后端启动流程；`prefill` 始终保持可见，直到新的 handoff 完成。
- `ensure_failure_fallback_window` 改成 `ensure_prefill_window`：失败恢复永远回到 `prefill`，不再把 `main` 伪装成 prefill。
- 用户在启动期间关闭 `prefill`，行为定义为整应用优雅退出。
- 启动期间若隐藏的 `main` 被销毁，定义为启动失败并回退到 `prefill` 失败态。

## APIs / Interfaces / Types
- `tauri.conf.json` 新增第二个窗口 `prefill`，并把 `main.url` 从 `prefill.html` 改为 `index.html#/loading`。
- 新增内部常量：`PREFILL_WINDOW_LABEL = "prefill"`。
- 保持 Tauri command 签名不变：
  - `notify_frontend_ready`
  - `report_loading_rendered`
  - `complete_startup_monitor_route`
  - `retry_start_backend`
- 事件目标调整：
  - `prefill-status` 改为发给 `prefill`
  - `shell-route`、`prefill-chat`、workspace session、open-request error 继续发给 `main`
- `NavigationState` 调整为：
  - 删除 `main_window_surface`
  - 将 `prefill_completion_pending` 重命名为 `handoff_requested`
  - 新增 `loading_rendered: bool`
  - 保留 `frontend_ready`、`queued_route`、`pending_main_events`、`pending_prefill`、startup watchdog 相关字段
- Rust 窗口管理 helper 重构为明确双窗口职责：
  - `create_prefill_window`
  - `create_hidden_main_window`
  - `finalize_startup_handoff`
  - `ensure_prefill_window`
  - `destroy_hidden_main_window`

## Test Plan
- 冷启动进入 `workspace`：prefill 可见，main 隐藏预热，最终直接显示 shell，无闪烁、无尺寸突变。
- 冷启动进入 `onboarding` / `diagnostics` / `control-center`：prefill 关闭后直接落到正确路由，无中间页暴露。
- 后端启动失败：prefill 留在前台，失败卡片、重试、打开日志、退出应用全部可用。
- `FrontendReadyTimeout`、`MainWebviewBuildHung`、`MainDestroyedDuringStartup`：都能回退到 prefill 失败态，且不会残留可见或隐藏的脏 `main`。
- 启动中触发托盘/快捷键显示窗口：应聚焦 `prefill`，不得提前暴露隐藏的 `main`。
- 启动失败后点击重试：旧 `main` 被销毁，新 `main` 重新隐藏预热，成功后正常 handoff。
- 启动前提交的 `prefill-chat`、启动期排队的 route 与 workspace session event，在 handoff 后仍能正确送达 `main`。
- 日志验收：
  - 不再出现 `main window prepared (... surface=prefill)`
  - 不再出现启动路径上的 `window.hide()` 后再 `navigate(shell)` 再 `show()`
  - 出现新的双窗口启动轨迹：`prefill shown -> hidden main created -> frontend ready -> loading rendered -> prefill closed -> main shown`

## Assumptions
- 本方案优先级是“彻底消闪”，不是“最小代码改动”。
- 本版本保留独立 prefill 产品形态，不把 prefill UI 合并进 shell 内部 overlay。
- `main` 在后台预热带来的额外启动成本可以接受，优先换取无闪烁 handoff。
- `index.html#/loading` 作为 `main` 的初始 URL 视为正式方案，不再保留运行时把可见窗口从 `prefill.html` 导航到 shell 的旧实现。
