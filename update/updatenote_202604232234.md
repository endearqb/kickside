# Update Note

Date: `2026-04-23 22:34`
Version line: `v0.0.39`

## Summary

This update makes Kimi Desktop Shell easier to configure, more explicit about auth state, and safer to ship as a public desktop build. The biggest user-facing change is that Kimi Provider API setup is now a simple one-key flow instead of an advanced config-editing task.

## Included Changes

1. **Kimi Provider API setup is simplified**
- The Control Center now shows a Kimi-only Provider API card.
- Users only need to enter one `API Key`.
- The endpoint is fixed and read-only:
  - `Kimi Coding Plan`
  - `https://api.kimi.com/coding/v1`
- Saving now writes the full Kimi provider/model/search/fetch template and keeps `设为默认` as a separate action.

2. **Auth-mode reporting is corrected**
- `Kimi 登录` and `Provider API` now have separate health semantics.
- Provider API failures no longer masquerade as login failures.
- Added a direct desktop `退出登录` action and clearer auth-card diagnostics.

3. **Release packaging is hardened**
- Packaged sidecar and bundled-skill lookup now defaults to packaged resources instead of workspace fallback.
- Added artifact / markdown path verification scripts to reduce accidental absolute-path leakage in public builds.
- Public build scripts now apply path remapping for release output.

4. **Desktop runtime flow is steadier**
- Prefill startup timing continues while the app is opening the main window instead of appearing frozen.
- Startup timeout thresholds are more forgiving on slower machines.
- Bundled skill discovery now supports both the current packaged layout and the older legacy `_up_` installer layout.

## User Impact

- Non-technical users can now configure Kimi Provider API without touching advanced TOML sections.
- Auth problems are easier to diagnose because login failures and Provider API failures are shown separately.
- Public release builds are less likely to depend on local workspace paths.
- Older installs have a better chance of recovering bundled skills without reinstalling.
