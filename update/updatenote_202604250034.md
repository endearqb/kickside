# Update Note

Date: `2026-04-25 00:34`
Version line: `v0.0.42`

## Summary

Today's update makes the local enhanced Kimi Web work more maintainable and more complete in Chinese without changing the runtime integration model. `v0.0.42` adds a tracked upstream `kimi-cli/web` source baseline, extends the same-origin injection pass to cover the main fixed UI paths, and keeps the official workspace proxy as the runtime host for enhanced mode.

## Included Changes

1. **Upstream Web source is now tracked locally**
- Synced `MoonshotAI/kimi-cli` `web/` into `third_party/kimi-cli-web/upstream-web/`.
- Recorded upstream commit `e32568cf2db0e95ad76878a4e6482986c8ecb180` across `SOURCE.md`, `manifest.json`, and third-party notices.
- Added maintainer guidance and patch-boundary docs so future local changes stay reviewable.

2. **The enhanced Web Chinese injection now covers more of the fixed UI**
- Expanded in-page same-origin injection beyond the initial empty-state/session labels.
- Added Chinese coverage for sessions/sidebar actions, create-session dialog copy, message search, workspace header controls, approval dialog controls, toast titles, and the front-end error boundary.
- Kept the injection boundary explicit: only fixed UI text, `placeholder`, `aria-label`, and `title` are translated.

3. **The runtime model stays stable**
- `官方 Web` / `本地增强版` switching behavior is unchanged.
- Enhanced mode still runs inside the existing workspace proxy response path, not through a local rebuilt upstream Web app.
- Official authentication, backend protocol, stream semantics, billing, and permission behavior remain unchanged.

4. **Dynamic payload text is still intentionally out of scope**
- Question payload bodies, approval descriptions, server error bodies, model output, and user-authored message content are not translated by this release.
- This avoids turning the injection layer into a fragile payload-level rewrite system.

## User Impact

- Users should now see a noticeably more complete Chinese fixed UI in the enhanced Web mode.
- The enhanced Web implementation is easier to maintain because the upstream source baseline is now recorded inside the repo.
- The official Web path remains the stable fallback, and the enhanced mode still does not fork service semantics.
